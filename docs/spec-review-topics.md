# 仕様書レビュー論点メモ

最終更新: 2026-04-02

このメモは、[ai-news-agent-spec.md](/Users/akihirookuda/work/ai-news-agent/docs/ai-news-agent-spec.md) を再レビューする際に、今後議論すべき論点を整理したもの。

## 1. 概要で引き続き詰める論点

- MVP の簡易音声はどこまでを許容範囲とするか
- 音声の入力は `md全文` ではなく `記事ごとの別要約` を前提にするか
- MVP の想定利用頻度をどう置くか
- 本プロダクトを `自分用ツール` として明記するか、将来的な一般化を見据えた表現にするか
- 「情報源の偏りを下げる」の判定基準をどこまで仕様に書くか
- 「重要度順」の評価軸を概要レベルでどこまで定義するか

## 2. スコープで詰める論点

- MVP の固定ソースをどこまでに絞るか
- Web 検索を MVP に含めるか、Phase 2 以降に回すか
- テックブログ収集を MVP 必須にするか
- 日本語ソースと英語ソースの優先順位をどうするか
- 音声生成を IN スコープに残す粒度をどこまでにするか
- OUT スコープへ明確に追い出す項目が他にないか

## 3. 情報ソース設計で詰める論点

- 固定ソースの選定基準をどう定義するか
- 各ソースの取得方法を RSS / Web / API のどれにするか
- Reddit や dev.to のようにノイズが多いソースをどう扱うか
- テックブログの優先順位をどう決めるか
- ソースの多様性をどう評価するか
- 同一話題を複数ソースで見つけたときに `重複` と `補強情報` をどう分けるか

## 4. 多段フェッチ戦略で詰める論点

- フォールバックに進む条件を何で判定するか
- `量` と `質` の閾値をどう定義するか
- 追加検索の段数上限をいくつにするか
- 処理時間 2〜3 分の制約下でどこまで探索を許すか
- フォールバックで広げすぎてノイズが増えるリスクをどう抑えるか

## 5. TUI 対話フェーズで詰める論点

- 最初の質問をどれだけ自由入力に寄せるか
- 追加質問を何問までに制限するか
- デフォルト値をどこまで設けるか
- `読む用途優先` を踏まえて音声質問を毎回出すか、省略可能にするか
- `abstractionLayer` の判定をユーザー明示にするか、推定にするか
- 対話を短く保ちながら必要十分な要求をどう取得するか

## 6. 翻訳仕様で詰める論点

- `完全翻訳` の対象範囲を本文だけにするか、コメントやメタ情報まで含めるか
- 長文記事をどの単位で分割翻訳するか
- 原文構造維持と日本語の読みやすさが衝突したときの優先順位をどうするか
- コード、表、箇条書き、引用の扱いをどこまで厳密に定義するか
- 翻訳品質の確認方法をどうするか

## 7. 音声ダイジェスト仕様で詰める論点

- MVP の簡易音声は何本の記事を対象にするか
- 1 本あたりの要約長を何秒にするか
- 全体の音声長を何分までに制限するか
- イントロやクロージングを MVP で省略するか
- 音声ファイル形式を MP3 に固定するか
- 音声品質向上フェーズで改善する項目をどこまで具体化するか

## 8. パフォーマンス目標で詰める論点

- `2〜3 分` の測定範囲をどこからどこまでにするか
- 5 件時と 10 件時で別目標を置くか
- 音声生成を含む場合の目標時間を別管理するか
- キャッシュ前提で測るか、コールドスタート前提で測るか
- 速度と翻訳品質が衝突したときの優先順位をどうするか

## 9. アーキテクチャで詰める論点

- Phase 1 の固定パイプラインと Phase 2 以降のエージェント化の境界をどう切るか
- `fetchRSS / webSearch / fetchTechBlog / checkDuplicate / scoreArticle` の責務分割をどうするか
- 音声生成処理を同一パイプラインに含めるか、後段の任意処理に分けるか
- エラー時の部分成功をどう扱うか
- 出力ファイルの保存先、命名規則、再実行時の上書き方針をどうするか

## 10. 出力フォーマットで詰める論点

- Markdown の見出し構造をこのままでよいか
- 重要度の段階を 3 段階で固定するか
- `要約` と `完全翻訳` の両方を同一 md に載せるか
- 音声リンクの表示位置をどこにするか
- ソース情報、日時、収集条件をどこまで明記するか

## 11. ロードマップで詰める論点

- 現在の各 Phase の作業量は週末開発の前提に対して妥当か
- Phase 1 に簡易音声を残すことで過負荷にならないか
- Phase 2 と Phase 3 の順番はこのままでよいか
- バッファ週の使い方をもっと明確化するか
- 締切 2026-04-20 に対して削る候補を先に決めるか

## 12. 成功基準で詰める論点

- Phase 1 の `満足レベル` をどう定義するか
- `重要度順が体感で正しい` をどう検証するか
- `情報源の偏りが下がった` をどう判断するか
- 音声の `聞ける品質` と `日常利用できる品質` の境界をどう置くか
- 成功基準に定量指標をどこまで入れるか
